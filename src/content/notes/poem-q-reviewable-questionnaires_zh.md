问卷题目写出来以后，通常还要经过一段不太整齐的准备期，才能进入正式的心理测量验证。构念已有理论定义，第一版题项池也已成形，但测量结构仍在调整。有些题目横跨多个维度，反向计分规则可能尚未写全，试测数据的列名也未必与问卷逐项对应。此时样本往往不大，统计结果更适合用来发现问题，而非给出定论。

[POEM-Q](https://github.com/inewhero/POEM-Q) 用来整理这段准备工作。它是一套基于 Dify 的 LLM Agent 工作流，在 EFA、CFA 或测量等值性分析之前检查问卷原型。工作流读取题项文件、构念定义、计分信息和可选的作答数据，输出一份 Markdown 报告。报告分别呈现原始证据、模型解释、代码计算结果，以及仍需研究者判断的问题。

POEM-Q 把问题放在效度判断之前：在招募更大样本之前，原型是否已经清楚到适合进入正式验证？仍然含混的题目和规则会留在报告中，供研究者修改或确认。

## 为什么使用 Agent 工作流

检查问卷原型时，几种性质不同的工作常常混在一起。理解构念定义与提取可观察行为，需要不同的阅读角度。识别潜在反向题，不能顺带解决维度归属；把题目对应到试测数据列，又要求一套更严格的匹配规则。

一个大 prompt 也能覆盖这些任务，但模型容易把推断过程压成一段看似顺畅、实际难以核对的答案。POEM-Q 把工作分给职责明确的节点，各节点先独立保存中间结果，再由后续节点汇总。

题项解析器保留原始顺序、标签、题干和作答锚点，同时为每道题分配稳定 ID。随后，几个定义 Agent 分别读取构念材料。它们提取理论定义与明确的计分规则，寻找可观察行为，并记录相邻构念之间的辨别性术语、语义反义关系和边界描述。

这些 Agent 回答的问题不同，因此没有必要用投票消除分歧。一个题项在理论上可能属于维度 A，行为措辞却更接近维度 B；带否定词的句子也可能只是语法否定，并非反向计分题。结构化节点会保留这类不一致，允许低置信度归属或暂不分配。研究者因此能看到争议发生在哪里。

## 从文本理解到原型评估

POEM-Q 分项呈现原型问题，不计算一个笼统的质量总分。研究者需要知道问题来自措辞、计分还是数据映射，才能决定如何处理。

语义检查关注题项措辞与目标构念是否一致，以及相邻维度有没有混淆。计分检查尝试从原始材料恢复作答范围和反向计分规则。数据检查则确认每道题能否可靠地映射到试测数据列。若同时提供作答数据，报告还会给出初步的内部一致性指标。

这样，报告讨论的是原型中哪些部分已经说清、哪些地方缺少证据，以及哪些决定应在正式验证前复核，而不是给量表笼统地下好坏判断。

计分方向有明确的证据顺序。原始材料注明的反向计分规则优先。文档没有说明时，LLM Agent 可以提出建议，并附上置信度和理由。最终报告始终区分原文规则与模型推断。

## LLM 负责解释，代码负责计算

提供作答数据后，工作流便进入数据处理。试测文件通常并不整洁，其中可能混有被试编号、人口学变量、空列和不一致的标签，数字作答有时还会与文字锚点同时出现。

POEM-Q 按固定顺序把题项映射到数据列。它先匹配完整题干，随后检查原始标签和题项 ID，只有前面的方法均失败时才使用受限的顺序回退。报告会记录每次回退、缺失匹配和冲突，避免问题在处理中悄悄消失。

映射完成后，确定性的 Python 节点执行反向计分，把题项统一缩放到 0 至 100，计算等权维度得分，并汇总缺失情况。数据条件允许时，代码还会计算 Cronbach's alpha、校正后的题总相关和删除某题后的 alpha。

语言模型接收的是已经算好的结果，不会在生成报告时再凭文本重算统计量。语义解释需要灵活的语言推理，数值运算则应在相同代码和输入下得到相同结果。两者分开后，研究者更容易检查计算来源。

## Embedding 作为第二层语义检查

POEM-Q 还使用 `BAAI/bge-m3` 比较题项与维度描述的 embedding 距离。这些距离是辅助检查线索，不是新的心理测量证据。

例如，一个归入维度 A 的题项，语义上可能更接近维度 B；另一个题项或许与所有维度定义都很疏远。研究者可以借此定位措辞歧义、构念重叠或定义缺口，但相似度本身无法证明题目有效或无效。

原型的标准维度得分因此继续采用透明的等权规则。Embedding 加权得分单独保存，并标记为探索性结果。它的用途是找到值得人工复核的位置，不能替代内容效度判断、因素分析或测量等值性检验。

## 两种运行模式

输入材料决定 POEM-Q 走哪条运行路径。

只有题项和构念定义时，工作流生成定义层面的原型评估报告，检查题项结构、维度归属、计分方向、语义歧义和缺失信息。

同时提供作答数据时，工作流会启用数据映射、计分、embedding 检查和初步内部一致性统计。条件节点记录实际执行的路径，最终报告只能引用上游真正完成的分析。

运行路径也划定了证据边界。定义报告不包含信度证据。试测数据报告可以描述当前样本的内部一致性，却不足以建立构念效度、诊断准确性、常模、截断分数或跨群体等值性。

## 可审查性是架构属性

POEM-Q 会保留 Agent 的中间解释、置信度、回退匹配和来源规则。研究者不必把输出当作黑箱结论，可以沿着这些记录查看报告是怎样形成的。

仓库中的 UCOC 材料目前用于 definition-only 路径的 smoke test，并非准确性 benchmark。成功运行说明解析、分支、计分和导出流程已经完成，但不代表每个题项归属都正确。

下一步开发会更关注 review interface。研究者需要逐项确认低置信度归属，比较问卷版本并记录 override；更正式的分析则应等到样本量和数据类型满足条件后再开放。这些功能比继续增加自动结论更能改善实际审查过程。

POEM-Q 把问卷原型开发中的解释工作组织起来。Agent 整理分散的早期材料，确定性代码处理数值计算，研究者则能回到原始规则和中间结果，判断题项是否需要改写、重新归类或继续收集证据。
